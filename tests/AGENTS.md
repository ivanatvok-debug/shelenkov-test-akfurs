# Проверки

Область: предметные тесты CLI Q1–Q4. `test_crm.py` проверяет частный Q1 через CLI на придуманных CSV; запуск — `.venv/bin/python -m unittest discover -s tests -p test_crm.py -v`. `test_bank.py` проверяет Q2 через API и CLI; запуск — `.venv/bin/python -m unittest discover -s tests -p test_bank.py -v`. Отдельные синтетические проверки инфраструктуры находятся в `data_skills/` и запускаются `.venv/bin/python -m unittest discover -s tests/data_skills -v`; они не подтверждают решение задания. Правила предметных примеров — в [fixtures/synthetic/AGENTS.md](fixtures/synthetic/AGENTS.md).

## Обязательные случаи

| Область | Что проверить |
|---|---|
| Входы | Отсутствующий файл, неверный формат, полнота чтения, скрытый лист XLSX |
| Q1 | Варианты номера с кириллицей, старый дубль, конфликт равных времён, смешанные статусы |
| Q2 | Контекст номера, чужие числа и телефоны, несколько заказов, исходящие операции, одинаковые суммы разных поступлений |
| Q3 | Обе скидки, количество больше одного, равенство минимуму, границы дат, замены артикулов, неизвестный артикул, канонические менеджеры |
| Q4 | Цена прописью, сумма клиента, предоплата, отрицание приглашения, отсутствие события, оба события в сообщении, порядок и роль, сбой AI |
| Контракт | Ровно десять ключей, типы, отсутствие Q5, stdout только с JSON, ненулевой выход при блокировке |
| Полный запуск | Холодный и повторный пересчёт, изменённые входы, новый чат, измеренная длительность |

## Доказательства

- Для Q1 сверяй баланс исходных, отброшенных и выбранных строк; для Q2 — количество и суммы поступлений; для Q3 — итог, менеджеров и построчные основания. Независимая сверка не должна повторять тот же ошибочный расчёт.
- Для Q4 проверяй каждый чат текущего корпуса по локальным основаниям и разбирай расхождения. Если доступна только выборка, указывай её охват; не заявляй отсутствие ошибок на непроверенных чатах.
- Проверяй ожидаемую реакцию на старый CRM-дубль, новое поступление, смену исторического минимума и перестановку приглашения/цены. Изменение текста должно пересчитывать Q4 без ручной правки ID.
- После изменения правила запускай зависимые проверки и пересчёт. Для реального исправления сохраняй случай, воспроизводящий дефект.
- В [журнале](../docs/review.md) указывай команду, результат, число проверок, среду, длительность и ограничения. Локальная синтетика не является закрытым эталоном работодателя.
