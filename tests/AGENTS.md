# Проверки

Все тестовые данные вымышлены или создаются во временных каталогах. Тесты запускают локальные процессы, заданные тестом. Проверка текущего набора не читает реальные входы.

## Общий набор

`test_output.py` проверяет десятипольный контракт, точность денег и взаимные ограничения. `test_end_to_end.py` проверяет полный CLI на четырёх синтетических файлах. Тест подменяет запуск Q4 локальным runner и проверяет повтор, изменения источников, отказ без частичного JSON и сохранность файлов.

`test_q4_adapters.py` проверяет разбор протоколов Codex/Claude, конфигурацию команд и ошибки на локальных фиктивных процессах. `test_chats.py` проверяет извлечение и оценку событий по синтетическим сообщениям и фикстурам ответов. Сохраняй регрессию для повреждённых событий и элементов. Проверяй, что изменение текста при прежнем ID пересчитывает Q4 без ручного изменения ID. Эти тесты не обращаются к модели и не доказывают живую совместимость провайдера. Живую проверку выполняй отдельно, только с разрешённым доступом и согласованным бюджетом.

Общий набор запускай из корня проекта:

```bash
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_*.py' -v
```

## Предметные тесты

- `test_crm.py` проверяет Q1 через CLI на синтетических CSV: `python -m unittest discover -s tests -p test_crm.py -v`.
- `test_bank.py` проверяет Q2 через API и CLI на синтетических CSV: `python -m unittest discover -s tests -p test_bank.py -v`.
- `test_pricing.py` проверяет Q3 через API и CLI на синтетических CSV/XLSX, включая скрытую историю: `python -m unittest discover -s tests -p test_pricing.py -v`.
- `test_chats.py` проверяет Q4 на синтетических TXT/ZIP и фиктивных ответах без обращения к модели: `python -m unittest discover -s tests -p test_chats.py -v`.
- Инструменты Skills проверяются отдельно: `python -m unittest discover -s tests/data_skills -v`. Эти тесты не подтверждают решение Q1–Q5.

При изменении общего читателя или нормализации проверяй зависимые области. При изменении отдельной области не выдавай старые проверки других областей за новые.

## Обязательные случаи

| Область | Что проверить |
|---|---|
| Входы | Отсутствующий файл, неверный формат, полнота чтения, скрытый лист XLSX |
| Q1 | Варианты номера с кириллицей, старый дубль, конфликт равных времён, смешанные статусы |
| Q2 | Контекст номера, чужие числа и телефоны, несколько заказов, списания, одинаковые суммы разных поступлений |
| Q3 | Обе скидки, количество больше одного, равенство минимуму, границы дат, замены артикулов, неизвестный артикул, канонические менеджеры |
| Q4 | Цена прописью, сумма клиента, предоплата, отрицание приглашения, отсутствие события, оба события в сообщении, порядок и роль, сбой AI, повреждённые события и элементы, изменение текста при прежнем ID без ручного изменения ID |
| Контракт | Ровно десять ключей, типы, отсутствие Q5, stdout только с JSON, ненулевой выход при блокировке |
| Полный запуск | Повторный расчёт, изменённые входы, новый чат, измеренная длительность при выполнении такого измерения |

## Параллельный Q4

Проверяй границы `workers`, число одновременно отправленных заданий, порядок реестра и раздельные выходы. При блокирующем сбое отправка новых заданий останавливается. Все уже отправленные задания должны быть учтены, в том числе при повреждённом `RUN.json`, ошибке ожидания или сбое координатора. Различай известное и неизвестное число вызовов. Неизвестный общий счётчик — `null`, итог — `HOLD`.

Синтетические тесты подтверждают только проверенные инварианты. Они не доказывают ускорение модели или смысловую эквивалентность полного корпуса.

## Доказательства

- Для Q1 сверяй баланс исходных, отброшенных и выбранных строк; для Q2 — количество и суммы поступлений; для Q3 — итог, менеджеров и построчные основания. Независимая сверка не должна повторять тот же расчёт.
- При полной смысловой проверке Q4 проверяй каждый чат и положительные, и отрицательные решения по исходным сообщениям; разбирай расхождения. Если проверена выборка, помечай её выборкой и указывай размер; не заявляй отсутствие ошибок в непроверенных чатах.
- После изменения правила запускай зависимые тесты. Для исправления дефекта сохраняй синтетический случай, который его воспроизводит.
- В [журнале](../docs/review.md) указывай команду, результат, число проверок, среду и ограничения. Синтетика не является закрытым эталоном работодателя.
