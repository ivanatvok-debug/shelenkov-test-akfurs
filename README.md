# AK Furs — тестовое задание AI-ассистента

Пересчёт Q1–Q4 из выгрузок CRM, банка, справочника цен и клиентских переписок. Q5 — отдельная записка руководителю и продолжение диалога C0010.

**Статус: G06 завершён по решению владельца — одного полного проверенного запуска Q1–Q4 достаточно для продолжения.** Общий CLI и схема JSON реализованы; первый полный JSON и все решения Q4 проверены. Q5 подготовлен и прошёл независимую проверку; локальный кандидат комплекта сдачи хранится в `private/`. История сбоя повторного запуска и ограничения среды сохранены; приёмка владельцем и отправка работодателю учитываются отдельно.

**Решение Ивана от 23.10.2026:** текущий результат G05-PERF удовлетворителен на данный момент. Вернуться к доработке и полному замеру после завершения основных GOAL; до этого вопрос отложен и не блокирует их выполнение. Технический HOLD полного замера и отдельный статус приёмки R2 сохраняются. Подробности — в [журнале решений](docs/review.md).

## Единый запуск Q1–Q4

В существующей проектной `.venv` с уже установленными `openpyxl`, `defusedxml`, `jsonschema` и доступным `codex exec`:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python solve.py data/ > answers.json
```

Проверенная среда — Linux, Python 3.12.3. Q4 использует POSIX-механизмы
`fcntl` и управления процессами; запуск на Windows этой реализацией не
подтверждён. Для другой машины с Linux получатель может подготовить отдельное
окружение командами ниже; в G08 установка зависимостей не выполнялась:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r tools/data_processing/requirements.lock
```

Доступный в `PATH` и уже настроенный `codex exec` требуется отдельно.
Credentials не входят в код или архив. Проверенные версии библиотек:
`openpyxl 3.1.5`, `defusedxml 0.7.1`, `jsonschema 4.26.0`.

Каталог должен содержать четыре файла с именами ниже. Каждый запуск заново считает Q1–Q4 из сырья, включая новый модельный анализ полного чата. Q4 передаёт тексты в OpenAI через имеющийся доступ `codex exec`; для такой передачи нужно разрешение владельца. До модельных вызовов проверяются наличие всех входов и готовность Q1–Q3. Зависимости и глобальные настройки команда не изменяет.

Успех: exit 0, в stdout ровно десять полей по [схеме](contracts/answers.schema.json), деньги — точные JSON-числа. Блокирующая ошибка: exit 2, stdout пуст, диагностика в stderr; созданный оболочкой `answers.json` тогда может быть пустым. Полный JSON не выдаётся при частичном успехе. Локальные основания, отдельные результаты и `RUN.json` сохраняются в новом `private/runs/<unique run>/`; `--evidence private/<new directory>` задаёт другой новый каталог. Входы и прежние evidence не перезаписываются. Не размещайте evidence внутри входного каталога.

`--q4-workers 1..4` задаёт число одновременно отправленных чатов, умолчание — 1; `--q4-timeout` — положительный таймаут одного чата в секундах, умолчание — 120. `run_command` сохраняет воспроизводимую команду с текущим Python, абсолютными путями и выбранными параметрами Q4; уникальный путь evidence опускается, чтобы повтор создавал новый каталог.

В передаваемом JSON поле `run_command` сохранено побайтно из принятого
запуска. Его абсолютные пути относятся к исходной машине; после переноса
используйте команду из корня проекта со своим Python и каталогом `data/`.
Переносимый вариант с параметрами проверенного полного запуска:
`.venv/bin/python solve.py data/ --q4-workers 4 > answers.json`.
Новый живой пересчёт этого варианта на другой машине не заявляется.

В G06 первый полный запуск с четырьмя workers прошёл все 150 чатов и независимую сверку по оригиналам: полный JSON, exit 0, 17 мин 11 с внешнего времени. Второй запуск остановился по native reconnect/timeout после 99 отправленных заданий; все они учтены, 51 не запускалось, stdout пуст. Третий запуск не начат. Итого 249 subprocess-вызовов, без повторов адаптера. Решение Ивана от 23.10.2026: «Остановимся на одном запуске, 1 проверки достаточно, переходим к дальнейшему выполнению тестового задания». Внутренний критерий трёх успешных запусков снят; проверенный первый результат принят как основа дальнейшей работы. Транспортный дефект не объявлен исправленным, исторические HOLD не переписаны. Серверный prefix cache отражается отдельно от отсутствия локального кэша ответов.

Проверки без передачи данных в модель:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

## Частный запуск Q1

Из корня проекта, в существующей `.venv`, с новым каталогом evidence:

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m akfurs.crm path/to/crm.csv --evidence private/q1-new-run
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_crm.py -v
```

Stdout содержит только частный `Q1_RESULT`, не `answers.json`. Источник — UTF-8 CSV с разделителем `;` и колонками «Номер заказа», «№ строки», «Выгружено»; время выгрузки — `YYYY-MM-DD HH:MM`. Все статусы участвуют в счётчиках. Неразобранные ключи и потеря строки удерживают Q1. Конфликт последних payload или невалидное время отдельно удерживает каноническую CRM, при достоверных ключах счётчики могут быть подтверждены. Ненулевой exit требует прочитать раздельные статусы в evidence. Готовность отбора CRM не подтверждает поля и правила Q2/Q3.

## Частный запуск Q2

Из корня проекта, с двумя исходными CSV и новым каталогом evidence:

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m akfurs.bank path/to/crm.csv path/to/bank.csv --evidence private/q2-new-run
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_bank.py -v
```

Q2 заново выбирает последние CRM-строки через `crm.py`. Банк читается как CSV с `;`, UTF-8/BOM или CP1251; поддерживается служебная строка выписки перед заголовком. Для связи нужен существующий номер в контексте заказа, сокращения `зак.`, счёта либо явного префикса A/А. Номер счёта трактуется как номер заказа — рабочее допущение R04; банковские реквизиты, телефоны и даты исключаются. Любое связанное поступление достаточно для исключения оплаченного заказа из Q2a: сумма, плательщик и дата не являются дополнительными фильтрами. Списания не подтверждают оплату, банковские операции не удаляются как дубли.

Stdout и `Q2_RESULT.json` содержат только Q2 с раздельными статусами Q2a/Q2b; это не полный `answers.json`. Точные денежные значения выводятся JSON-числами без промежуточного float. В evidence сохраняются все исходные банковские записи, кандидаты ссылок, CRM-основания и денежный баланс. Неоднозначные ссылки, ошибки чтения и смешанные статусы выбранных строк удерживают зависимую область; невычисленные поля отсутствуют, exit ненулевой. Старый каталог evidence не перезаписывается.

## Частный запуск Q3

В существующей `.venv`, с исходными CRM CSV и каталогом XLSX, включая скрытые листы:

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m akfurs.pricing path/to/crm.csv path/to/catalog.xlsx --evidence private/q3-new-run
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_pricing.py -v
```

Q3 использует последние CRM-строки из `crm.py`; исключает только отменённые. Исторический минимум выбирается на дату создания, после явного переименования артикула. Границы периодов включительны, пустой конец открыт. Slash-даты трактуются DD/MM, serial — от 1899-12-30; aliases применяются независимо от даты переименования. Фиксированная скидка вычитается один раз на всю строку; процентная — от `price × quantity`. Точное сравнение `net_total < minimum × quantity` не округляет цену единицы: равенство не является нарушением.

Выход — частный `Q3_RESULT.json` с общим числом и положительными группами по каноническим менеджерам, отдельными статусами итога/разбивки; это не полный `answers.json`. Построчные основания и полнота сохраняются в новом каталоге evidence. Неопределённые существенные даты, цены, aliases, история или менеджеры удерживают зависимый ответ; невычисленные поля не заменяются нулём. Пересчёт Q1–Q3 и AI-review сами по себе не означают приёмку R1 владельцем.

## Частный запуск Q4

В существующем проектном окружении Python с `jsonschema` и настроенным доступом установленного `codex exec`:

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m akfurs.chats path/to/chats.zip --evidence private/q4-new-run
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_chats.py -v
```

Каждый чат передаётся полностью в новый вызов модели, без resume и кэша ответов адаптера. Параметр `--workers` принимает значения от 1 до 4; по умолчанию используется один поток, как в измеренном последовательном baseline. В парной выборке G05-PERF режим `--workers 4` дал наблюдаемое ускорение 3,34 раза (200,82 → 60,19 с). Новый полный запуск остановлен транспортной ошибкой; ускорение на полном корпусе и готовность оптимизации — `HOLD`. Временный пустой cwd создаётся программно; приватный путь пилота не требуется. Код проверяет структуру/роли, точные цитаты, Unicode-границы и порядок, затем вычисляет нарушение. Для предметного PASS дополнительно проверяется смысл всех чатов по оригиналам: корректная цитата сама по себе не доказывает полноту извлечения.

Одновременно отправляется не больше указанного числа чатов. При блокирующем сбое новые задания прекращаются, уже отправленные учитываются до завершения; ещё не начатые остаются `NOT_CHECKED`, весь ответ — `HOLD`. Реестр сохраняет порядок исходного ZIP. `RUN.json` отдельно сохраняет native timing координатора и сумму длительностей subprocesses; полное время CLI измеряется внешним замером для G05-PERF.

Цена изделия от менеджера может быть прописью, «от» или диапазоном; клиентский бюджет и отдельные аванс/платёж/скидка её не заменяют. Действительное приглашение, включая вежливое условие, раньше первой цены либо без цены означает нарушение. Нет приглашения — нет нарушения. В одной реплике сравниваются минимальные достаточные неперекрывающиеся цитаты; отрицания, цитирование и гипотезы различаются. Неоднозначность или сбой дают HOLD/ненулевой exit, успешного частичного Q4 нет.

Результат, полный реестр, запросы/ответы, журнал вызовов и измерения сохраняются только в новом приватном каталоге. Read-only sandbox не является полной изоляцией чтения; исходные тексты обрабатываются как данные, инструкции из них не исполняются. В `AKFURS-G05-PERF` после успешной выборки полный запуск остановился при native reconnect/timeout: учтены все 24 отправленных задания, 126 не запускались. Все доступные ответы проверены по источнику, но полной смысловой эквивалентности нового запуска нет; упаковка HOLD не означает готовность оптимизации. Предметная политика сохранена. Утверждение R2 остаётся решением владельца.

## Входы и будущий запуск

Исходный комплект хранится локально в `inbox/`: четыре выгрузки, шаблон ответа и ТЗ. Для будущего запуска предусмотрен отдельный `data/` с четырьмя файлами без переименования и ручного редактирования:

```text
data/
├── 01_crm_orders_export.csv
├── 02_bank_statement_rub.csv
├── 03_catalog_prices_reference.xlsx
└── 04_client_chats.zip
```

`inbox/` сохраняется без изменений; `data/` сейчас пуст. Оба каталога исключены из Git. Шаблон и ТЗ определяют правила, но не являются операционными входами CLI. XLSX нужно сохранять целиком со скрытыми листами.

Короткая форма интерфейса (при выбранном Python с нужными зависимостями):

```bash
python solve.py data/ > answers.json
```

Общий запуск пересчитывает весь JSON из сырья. В stdout допускается только полный JSON, диагностика направляется в stderr; блокирующая ошибка означает ненулевой код завершения. Частные CLI используют ту же проектную `.venv`; Q4 — установленный `codex exec` через текущий доступ OpenAI. Дополнительная живая серия не требуется по решению владельца; среда работодателя не проверена.

## Проверки и ограничения

Для отдельно разрешённой работы с данными доступны четыре Skills в
`.agents/skills/`: `akfurs-xlsx`, `akfurs-data-quality`, `akfurs-reconciliation`,
`akfurs-validation`. Они используют проектную `.venv` и один вспомогательный
CLI, не выполняющий Q1–Q5:

```bash
.venv/bin/python -m tools.data_processing --help
.venv/bin/python -m unittest discover -s tests/data_skills -v
```

Установка, контракты, ограничения и примеры — в [инструкции стека](docs/data_skills/USAGE.md).
Исходники Hermes и лицензии — в [SOURCE_MANIFEST](docs/data_skills/SOURCE_MANIFEST.md).
Наличие Skills не даёт разрешения на обработку реального комплекта.

Проверки и границы фиксируются в журнале ревью. Для Q1–Q4 существуют предметные синтетические проверки; evidence запуска и независимой сверки хранится вне Git. Первый полный свежий пересчёт Q1–Q4 подтверждён и признан владельцем достаточным для продолжения; три успешных запуска не заявляются. Сверка со скрытым эталоном работодателя не выполнена.

Исходные данные, `answers.json`, Q5 и AI-экспорты не входят в Git. Локальный комплект содержит проверенный JSON первого запуска, Q5, кодовый снимок с настоящей историей и незакоммиченным patch, очищенный экспорт видимых сообщений AI-сессии и подлинные доказательства найденной ошибки агента. Полная внутренняя сессия не заявляется экспортированной. R3 и отправка — `NOT_CHECKED`. Решение предназначено для конкретного задания; промышленная автоматизация ателье не входит в его область.
