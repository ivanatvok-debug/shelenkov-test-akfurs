# AK Furs — тестовое задание AI-ассистента

Один Python CLI пересчитывает Q1–Q4 из CRM, банковской выписки, исторического прайса и переписок. Q5 передаётся отдельно. Текущий FINAL — локальный кандидат, подготовленный к рассмотрению и передаче. 24.10.2026 владелец поручил пропустить дальнейшие работы Q4 и завершить остальное. Проверенный Q4 сохранён: полный холодный запуск — 17 мин 15,4 с. Достижение «нескольких минут» отложено и не заявляется. Приёмка владельцем, доступ получателя и отправка учитываются отдельно.

## Среда и подготовка

Проверенная среда: Linux, Python 3.12.3. Для Q4 нужны POSIX `fcntl` и управление группой процессов. Windows и новая установка на машине получателя не проверены.

Подготовьте окружение отдельно от расчёта:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r tools/data_processing/requirements.lock
source .venv/bin/activate
```

Это инструкция установки; новая установка в FULL не выполнялась. Runtime использует `openpyxl`, `defusedxml`, `jsonschema` и стандартную библиотеку. Тесты используют `unittest`. Установленные Skills не нужны для запуска.

Отдельно нужен доступный `codex exec` с входом через ChatGPT. Проверенная версия CLI — `0.163.0`. Адаптер задаёт конфигурацию только на вызов: отдельный provider ID для OpenAI, ChatGPT auth, запрошенные HTTP/stream-повторы = 0, read-only sandbox, временный пустой cwd и ephemeral session. Глобальный config не редактируется. CLI может записывать своё служебное состояние вне проекта; доступ к нему нужен среде запуска. Наблюдался отдельный механизм waiting for network даже при этих настройках. Все внутренние сетевые попытки клиент не раскрывает; нулевое их число не заявляется.

Код не покупает credits и не меняет подписку. Включённые лимиты, отключённое автопополнение и разрешение передачи данных проверяются владельцем перед живой работой. Запуск передаёт полные переписки в OpenAI; зависимости и аутентификация скрыто не устанавливаются.

## Входы и команда

Поместите четыре файла в `data/` без ручного редактирования:

```text
data/
├── 01_crm_orders_export.csv
├── 02_bank_statement_rub.csv
├── 03_catalog_prices_reference.xlsx
└── 04_client_chats.zip
```

Сохраните XLSX целиком со скрытыми листами. Исходный `inbox/` не меняется. Пустой каталог не означает наличие данных.

Из корня проекта с подготовленным Python:

```bash
python solve.py data --q4-max-calls 330 --q4-budget-seconds 2275.0 --q4-workers 4 > answers.json
```

Это переносимая запись конфигурации полного запуска. Живой запуск дополнительно задавал уникальные пути evidence/ledger; точные argv сохранены во внешнем отчёте. Лимит 2275 с — остаток согласованной серии того запуска, а не обещание времени. Полный результат: 150/150 чатов. Сохранённые 138 тестов без моделей относятся к той же расчётной версии; финальные изменения затрагивают документацию. Человеческая приёмка отдельно.

`--q4-workers` допускает 1–4, умолчание — 1. `--q4-timeout` задаёт таймаут чата, умолчание — 120 с. При необходимости ограничьте серию через `--q4-max-calls`, `--q4-call-ledger` и `--q4-budget-seconds`. Ledger и evidence должны находиться вне входного каталога. Реально использованная конфигурация сохраняется в `run_command`; уникальные пути evidence/ledger туда не входят. Команда рассчитана на запуск из корня проекта.

Успех: exit 0 и ровно десять полей [контракта](contracts/answers.schema.json) в stdout. Деньги сохраняются точными JSON-числами. Ошибка: exit 2, пустой stdout и безопасная причина в stderr. Shell может создать пустой `answers.json`; это не результат. Полные основания сохраняются в новом `private/runs/<unique>/` или новом каталоге `--evidence`. Сырьё и прежние evidence не перезаписываются.

Каждый запуск заново читает входы и выполняет AI-анализ. Готовые ответы не используются. Локального answer cache/resume нет. Серверный prefix cache отражается отдельно в usage. Изменение текста при прежнем ID пересчитывается.

## Claude и границы проверки

`--q4-provider claude --q4-model <точная модель>` выбирает подготовленный Claude CLI adapter. Он использует ту же предметную схему и проверку цитат/ролей/порядка. Модель для Claude надо задать явно; код не выбирает платный API. Потребуется отдельно подготовленный `claude`, совместимый с документированными флагами, и согласованный доступ.

Уровень текущей проверки Claude — локальные протокольные фикстуры и настоящие локальные child processes. CLI отсутствует в текущей среде; живые вызовы Claude не выполнялись. Это не доказательство совместимости с установленной версией Claude. Детали — в [архитектуре](docs/ARCHITECTURE.md).
