# Архитектура AK Furs

Один Python CLI рассчитывает Q1–Q4 по исходным данным. Q1–Q3 обрабатываются детерминированным кодом. Для Q4 языковая модель выделяет события из переписок, а Python проверяет ответ и определяет порядок событий. Q5 готовится отдельно.

## Структура проекта

```text
solve.py
src/akfurs/
  crm.py
  bank.py
  pricing.py
  chats.py
  q4_adapters.py
  solver.py
  output.py
  q4_resources/
    prompt.txt
    response.schema.json
    POLICY.md
contracts/answers.schema.json
tests/test_*.py
tools/data_processing/
```

`inbox/` хранит оригиналы задания, `data/` содержит четыре входных файла для расчёта. Оба каталога исключены из Git. Результаты и основания расчётов сохраняются отдельно.

## Q1–Q3: обработка данных

### CRM

`crm.py` читает CSV, нормализует идентификаторы заказа и строки и выбирает последнюю выгрузку для каждой пары. Если записи с одинаковым максимальным временем содержат разные данные, расчёт останавливается с ошибкой.

Счётчики учитывают все статусы. Сохраняется учёт выбранных, отброшенных, конфликтных и неразобранных записей.

### Банковская выписка

`bank.py` связывает поступления с существующими заказами по назначению платежа. Сумма, телефон, дата и плательщик сами по себе не служат основанием для связи.

Для Q2a достаточно любого связанного поступления. Списания не учитываются как поступления; полная оплата заказа не требуется. Операции с одинаковыми суммами не удаляются как дубликаты только на этом основании.

### Исторический прайс

`pricing.py` использует выбранные CRM-строки и XLSX-читатель `tools/data_processing/xlsx.py`. Читатель учитывает скрытые листы и числовые значения из XML, различает формулы и сохранённые результаты. Формулы не пересчитываются.

Минимальная цена определяется на дату создания заказа. Переименования товаров и имена менеджеров сопоставляются по справочникам.

Для проверки используется сравнение:

```text
net_total < minimum × quantity
```

Фиксированная скидка вычитается один раз из суммы строки. Процентная скидка применяется к произведению цены и количества. Промежуточное округление не выполняется; равенство минимальной цене не считается нарушением.

## Q4: анализ переписок

### Подготовка данных

`chats.py` читает ZIP, разбирает все сообщения и сохраняет исходные TXT. Каждому сообщению назначается идентификатор `chat_id:position`. Позиции нумеруются с единицы.

В модель передаётся одно представление сообщений без повторного включения исходного TXT. Для задания сохраняются идентификаторы, хеш содержимого, версии промпта и схемы, а также таймаут.

### Модель и адаптеры

Общие правила анализа, промпт и схема ответа находятся в `q4_resources/`. Модель извлекает события: сообщения менеджера с ценой и приглашением, их позиции и цитаты.

`q4_adapters.py` отвечает за запуск CLI и разбор его протокола. Поддержаны два адаптера:

- **Codex:** настройки задаются на отдельный вызов, без изменения глобальной конфигурации; используется авторизация ChatGPT. Распознанное переподключение допускается, если после него получен завершённый корректный ответ.
- **Claude:** используется структурированный ответ по JSON Schema; модель указывается явно. Инструменты и пользовательские настройки отключаются соответствующими CLI-флагами.

Адаптеры возвращают единый результат: статус, извлечённые события и доступные сведения о модели, использовании токенов и времени. Если сведения не предоставлены CLI, они остаются неизвестными. Число запущенных процессов учитывается отдельно от внутренних сетевых запросов.

### Проверка и итоговое решение

Оба адаптера используют общий `evaluate()`. Он проверяет:

- соответствие схеме и наличие обязательных данных;
- позиции сообщений, отсутствие дублей и роль автора;
- точное присутствие и однозначность цитат в исходном тексте;
- границы цитат и порядок событий.

Общие правила различают цену изделия от менеджера, бюджет клиента, отдельный аванс, отрицание и цитирование приглашения.

Приглашение до первой цены или при отсутствии цены считается нарушением. Если приглашения нет, нарушения нет. Для событий в одной реплике сравниваются начала достаточных неперекрывающихся цитат.

Проверка цитат подтверждает связь ответа с исходным текстом, но сама по себе не гарантирует правильность смысловой классификации или полноту найденных событий.

## Управление запуском и результат

`solver.py` проверяет входные файлы и лимиты до запуска Q4. Создаёт новый каталог оснований расчёта и сверяет хеши исходников до и после обработки.

Q4 выполняется в 1–4 параллельных процессах. Для заданий используются отдельные каталоги и общий журнал вызовов с файловой блокировкой. При блокирующей ошибке новые задания не отправляются; уже отправленные учитываются. Порядок чатов в реестре соответствует ZIP.

Общий бюджет времени ограничивает отправку заданий и их таймауты. Ошибки выполнения, неполные ответы, невалидные объекты и выполнение посторонних инструментов блокируют выдачу итогового результата.

`output.py` собирает десять полей и проверяет [контракт ответа](https://github.com/ivanatvok-debug/shelenkov-test-akfurs/blob/main/contracts/answers.schema.json). Денежные значения сохраняются как точные JSON-числа.

- Успех: код завершения `0`, полный JSON в `stdout` после сохранения оснований расчёта.
- Ошибка: код завершения `2`, пустой `stdout`, причина в `stderr`.

Локального кэша ответов, возобновления прерванного расчёта и пакетной обработки чатов нет. Каждый запуск выполняет новый AI-анализ. Серверное кэширование префикса учитывается отдельно в статистике использования токенов.

## Проверка и ограничения

- **Codex:** полный запуск на 150 чатах; последующая сверка всех решений с сохранёнными AI-основаниями и исходными сообщениями не выявила расхождений.
- **Claude:** локальные протокольные тесты и тесты дочерних процессов. Живой запуск через Claude не проверен.
- **Среда:** Linux и POSIX-механизмы. Работа на Windows не проверена.
- **Скорость:** полный холодный запуск занял 17 мин 15,4 с. Время измеряется для всего CLI; сумма длительностей параллельных процессов учитывается отдельно.

Дальнейшая оптимизация Q4 оставлена за рамками бесплатного тестового задания по решению автора. Возможные направления: компактные ссылки на сообщения вместо длинных цитат, обработка нескольких чатов за вызов и прямые API-вызовы с управляемой параллельностью. Изменения требуют проверки качества и измерения скорости.
