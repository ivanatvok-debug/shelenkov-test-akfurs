# Архитектура AK Furs

Один CLI пересчитывает Q1–Q4. Q5 готовится отдельно. Предметная логика не зависит от установленного редактора или Skills. Рабочий Q4 использует явно выбранный CLI transport. Запуск на другой модели и запуск другим coding-агентом — разные свойства.

## Рабочий путь

```text
solve.py
src/akfurs/
  crm.py
  bank.py
  pricing.py
  chats.py
  q4_adapters.py
  solver.py
  output.py
  q4_resources/{prompt.txt,response.schema.json,POLICY.md}
contracts/answers.schema.json
tests/test_*.py
docs/{REQUIREMENTS_MATRIX.md,review.md,EMPLOYER_REVIEW_GUIDE.md}
```

`inbox/` хранит неизменяемые оригиналы. `data/` — четыре входа запуска. Их наличие проверяется программой; оба каталога исключены из Git. Приватные результаты и история проверок хранятся отдельно. Старые упаковщики не участвуют в runtime.

## Q1–Q3 и полный JSON

`crm.py` читает строгий CSV, нормализует пару заказ/строка и выбирает максимальное время выгрузки. Разные payload на равном максимуме блокируют каноническую CRM. Счётчики включают все статусы. Баланс сохраняет выбранные, отброшенные, конфликтные и неразобранные записи.

`bank.py` связывает поступления только с существующим заказом по контексту назначения. Сумма, телефон, дата или плательщик не доказывают связь. Для Q2a достаточно любого поступления; списания и критерий полной оплаты не подменяют ТЗ. Совпадение сумм не является основанием удаления банковской операции.

`pricing.py` использует те же выбранные CRM-строки и ограниченный `tools/data_processing/xlsx.py`. Читатель учитывает скрытые листы, типы, exact XML numbers и раздельные formula/cache. Формулы не пересчитываются. Минимум выбирается на дату создания, aliases и менеджеры — по явному справочнику. Сравнение `net_total < minimum * quantity` исключает преждевременное округление. Фиксированная скидка снимается один раз со строки; процентная применяется к цене × количеству. Равенство минимуму не является нарушением.

`solver.py` проверяет четыре входа и лимиты до Q4, создаёт новый evidence и сверяет исходные хеши до/после стадий. Повторное чтение CRM существующими API сохранено: небольшая экономия CPU не оправдывает новый слой общего состояния. `output.py` собирает ровно десять полей, проверяет JSON Schema и взаимные ограничения. Serializer из `bank.py` сохраняет Decimal как точные JSON-числа. Полный JSON появляется только в stdout после успешной финализации evidence. Сбой даёт exit2 и пустой stdout.

## Q4: данные, транспорт, решение

Цепочка: ZIP inventory → полный `chat.messages` → общий prompt/policy/schema → выбранный CLI → transport decode → общая локальная schema/quote/role/order validation → предметный результат.

`chats.py` строго разбирает все сообщения и сохраняет исходный TXT. Каждый message получает устойчивый ID `chat_id:position`; semantic response использует прежнюю 1-based `position`, однозначно связанную с этим ID. В запрос передаётся одно представление реплик; raw TXT не повторяется. В `job` записаны job/chat ID, content hash, версии prompt/schema и timeout. Идентификатор чата или число чатов не зашиты в предметную логику.

`q4_adapters.py` содержит только команды и разбор протоколов Codex/Claude. Модель возвращает предметные события. Контракт provider metadata содержит статусы: `ok`, `refused`, `truncated`, `invalid`, `transient_error`, `permanent_error`, доступные model/usage/elapsed и счётчик процессов. `request_id` — доступный CLI thread/session correlation ID одного задания; отдельный HTTP request ID не наблюдается. Неизвестная модель или число внутренних серверных попыток остаются `null`/`NOT_CHECKED`. Число процессов не выдаётся за число серверных запросов.

Codex получает отдельный provider ID `akfurs_openai` с OpenAI auth, принудительным ChatGPT login, `request_max_retries=0` и `stream_max_retries=0`. `--strict-config` удерживает запуск при несовместимых ключах. Перезапись зарезервированного `openai` не используется. Конфигурация задаётся в argv, общий config не меняется. Отдельный механизм waiting for network наблюдался даже при этих значениях; предел всех внутренних сетевых попыток не подтверждён и раскрывается до запуска. Разрешено только распознанное сообщение reconnect с последующим завершением; `turn.failed`, неизвестная ошибка, timeout, неполный ответ, tool execution или невалидный объект удерживают результат. Это не исправление внешней сети или native timeout.

Claude использует `-p`, `stream-json --verbose`, `--json-schema` и конечный `structured_output`. Допустима только одна конечная result-запись. Built-in/MCP tools и пользовательские customizations выключаются доступными CLI-флагами; `StructuredOutput` различается с пользовательским tool execution. Модель задаётся явно. `--bare` не навязывается: он меняет способ аутентификации. В текущей среде Claude отсутствует; проверены только придуманные протоколы и локальные child processes. Уровень live-совместимости не заявляется.

Оба транспорта вызывают один `evaluate()`. Он проверяет схему, полноту, позиции, дубли, роль, уникальность exact quote, Unicode spans и порядок. Цена изделия от менеджера, клиентский бюджет, отдельный аванс и отрицание/цитирование приглашения различаются по общей policy. Приглашение до первой цены либо без неё — нарушение; без приглашения нарушения нет. В одной реплике сравниваются начала достаточных неперекрывающихся цитат.

## Ограничения исполнения и основания

Координатор использует 1–4 workers, раздельные каталоги и общий ledger с file lock. При блокирующем сбое он не отправляет новые задания и учитывает уже отправленные. Реестр сохраняет ZIP order. Для неизвестных вызовов используется `null`, не ноль. Общий deadline прекращает dispatch и ограничивает timeout уже запускаемого задания; конец серии включает drain и запись evidence.

Локальный answer cache/resume и batching не добавлены. Ключ потенциального будущего cache должен учитывать содержание, provider/model/параметры и версии prompt/schema/policy. Серверный prefix cache уже отражается в usage. Холодный полный запуск и повтор измеряются отдельно внешним wall clock; сумма времён subprocesses не заменяет полное время CLI.

Exact quote validation не доказывает смысл и полноту. Контрольные AI-основания G06 сохраняются с авторством и raw hashes; новые решения сверяются по исходным сообщениям и позициям всех manager price/invitation событий. Расхождения требуют чтения оригинала, а не согласия агрегатов. Скрытый эталон и человеческая приёмка отсутствуют.

Вспомогательный `tools/data_processing/` и четыре `.agents/skills/akfurs-*` обеспечивают ограниченные операции и синтетические проверки. Они не являются контрактом `answers.json` и не заменяют предметный validator Q4. Runtime-licensing/provenance — [SOURCE_MANIFEST](data_skills/SOURCE_MANIFEST.md).

Версии, фактические времена, состав кандидата и разрешения — в текущем внешнем HANDOFF. [review.md](review.md) сохраняет исторические решения без переписывания старых HOLD. Решение об одном полном G06 и отложенном PERF остаётся историческим основанием; оно не заменяет новый выпускной запуск изменённого Q4.

Текущая граница проверки: Codex — полный live 150/150, затем source-grounded сравнение всех решений без расхождений; Claude — только offline по решению владельца. Повтор полного набора NOT_RUN: разрешён один новый полный запуск. Новое ускорение пока только планируется, текущий пакет не содержит batching/cache.

24.10.2026 владелец поручил пропустить дальнейшие работы Q4 и завершить GOAL. Расчётная версия и полный проверенный результат сохранены. Ускорение остаётся отложенной работой; фактическое время не переименовано в достигнутый критерий. Финальное изменение документации не требует нового модельного расчёта.
