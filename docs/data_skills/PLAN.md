# AKFURS-B-01 — план локального стека Skills

**Источник требований:** предоставленный `goal-objective.md`, GOAL AKFURS-B-01.
**Цель:** четыре проектных Skills и проверенные инструменты для синтетических
CSV/XLSX и структурированных записей; решение Q1–Q5 в этот этап не входит.
**Метод:** локальная реализация по шагам, тесты до кода, отдельное AI-ревью
после реализации; приёмка владельцем остаётся отдельной.

## Проектирование и границы

- `.agents/skills/akfurs-{xlsx,data-quality,reconciliation,validation}/SKILL.md`
  содержат условия вызова, ограничения, команды, ошибки и критерии результата.
- `tools/data_processing/` — один вспомогательный Python CLI с небольшими
  модулями `tabular`, `quality`, `reconciliation`, `validation`, `cli`.
  Предметный `src/akfurs` и будущий `solve.py` не меняются.
- `tests/data_skills/` — синтетические фикстуры, положительные, отрицательные
  и интеграционные проверки. Файлы генерируются в временном каталоге.
- `docs/data_skills/` — происхождение, зависимости, инструкция и handoff.
  Фактический журнал решений — существующий `docs/review.md`.
- `.venv/` — изолированная среда; полный lock с версиями и hash пакетов.
  Предварительный минимум: openpyxl, jsonschema, pytest; стандартная
  библиотека для CSV, Decimal, дат, нормализации и fuzzy-кандидатов.
- Новые результаты CLI разрешены только под `private/data_skills/`.
  Существующий файл не перезаписывается, исходник никогда не сохраняется.
  Экспорт не исполняет формулы, макросы, подключения или команды из данных.
- Реальные `inbox/`, `data/`, чаты, шаблон ответов и ТЗ не обрабатываются.
  Схемы этого этапа относятся только к синтетическому протоколу инструментов.
  Они не объявляются контрактом работодателя.
- Нет глобальной установки, изменения ~/.codex, commit, push или публикации.

## Факты и допущения

Факты старта: исходный проект содержит только оформление; Git чистый, ветка main,
HEAD `fca6b27`. Четырёх Skills и Python-среды нет. Python 3.12.3,
Codex 0.163.0, uv 0.11.22 и LibreOffice доступны. `.agents/` существует,
но защищён от записи текущей песочницей.

Допущения: отдельный вспомогательный CLI не меняет архитектуру будущего
решения; точный выбор библиотек уточняется после проверки исходников.
Нормализация и правила сопоставления требуют явного контракта пользователя,
не знания предметных правил AK Furs.

## Риски и проверки проектирования

| Риск | Решение | Проверка |
|---|---|---|
| Потеря ведущих нулей и raw values | CSV читается как текст, raw и normalized разделены | CSV→XLSX→CSV, сравнение значений |
| Формулы без cached values | Формулы и кэш читаются раздельно; отсутствие движка — отказ | T04, T16 |
| CSV injection | Строковые ячейки принудительно имеют текстовый тип | Опасные префиксы в XLSX и безопасный CSV-экспорт |
| Ложное финансовое совпадение | Только заданные ключи, валюта, Decimal и явные допуски | T07–T11, T15, отрицательные cases |
| Двойное использование платежа | Учёт использованных ID, группировка только с явным распределением | T10, распределения/возвраты |
| Самоподтверждение ошибочного результата | Валидатор заново считает по исходным записям, не вызывает matcher | Инъекция ошибок, покрытия и исключения |
| Утечка или перезапись | Нет сетевого кода в runtime, строгая выходная директория, отказ при существовании | T14, symlink/path traversal, CLI errors |

## Checkpoints и критерий остановки

CP-0: правильный проект и scope; CP-1: происхождение/лицензия/security;
Gate A: структура; B: безопасность; C: функции; D: целостность;
E: корректные matches; F: независимая валидация; G: интеграция.
PASS требует сохранённого evidence. Недоступное — NOT_CHECKED,
критическая неизвестность — HOLD зависимого действия.

DoR: известны цель, владелец, границы, входы, AC, разрешения и средства.
DoD: рабочие артефакты, доказательства T01–T16, лицензия, lock, review,
ограничения, документация. Owner acceptance не подменяется AI-review.
Финальный статус целевого пакета: READY FOR OWNER REVIEW — NO COMMIT.
