# Документация и передача

Область: Markdown-документы, записи ревью и правила подготовки Q5. Локальные Q5, доказательства и AI-экспорты хранятся в `private/`, вне Git.

## Документы

- Держи README короткой точкой входа; структуру и зависимости описывай в [ARCHITECTURE.md](ARCHITECTURE.md), просмотр и сдачу — в [EMPLOYER_REVIEW_GUIDE.md](EMPLOYER_REVIEW_GUIDE.md).
- Веди один [review.md](review.md) для смысловых решений, ошибок, проверок и приёмки R0–R3. Не создавай параллельные журналы.
- Различай требование работодателя и проектный критерий, план и существующий файл, самопроверку и решение владельца. Не ставь `PASS` вместо отсутствующей проверки.
- Проверяй ссылки. Для отсутствующих модулей, схемы и тестов используй текстовые планируемые пути без ссылок на несуществующие файлы.
- Передавай этап с изменёнными путями/коммитами, проверенными требованиями, командами и числом тестов, ошибками и их влиянием, безопасными ссылками на доказательства, статусом и следующим разрешённым шагом.
- Не называй работу принятой без решения владельца; не придумывай ошибки AI и историю разработки. Итоговые смысловые трактовки должны совпадать с `notes`.

## Q5

- Готовь Q5 только по принятым Q1–Q4. Записка руководителю: три вывода с цифрами, две рекомендации, не больше половины страницы, без необходимости читать код.
- Для ответа C0010 учитывай сведения, доступные на момент переписки. Не выдумывай цену, наличие, скидку, обещания или намерения клиентки; сохраняй уместный тон менеджера ателье.
- Передавай Q5 отдельно от JSON после проверки цифр и контекста. Полный текст с данными не добавляй в Git.
