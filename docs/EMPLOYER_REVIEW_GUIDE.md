# Просмотр и сдача решения AK Furs

**Реализованы Q1–Q4, общий CLI, схема ответа и предметные тесты; Q5 прошёл независимую проверку.** Первый полный живой запуск и сверка его Q4 по оригиналам пройдены; владелец признал одной проверки достаточно для продолжения. Второй запуск остановлен по native timeout/reconnect, третий не начат; это сохранённое техническое ограничение. Локальный кандидат комплекта сдачи подготовлен в `private/`; приёмка владельцем/R3 и отправка — `NOT_CHECKED`. Синтетические сквозные тесты учитываются отдельно от живого пересчёта.

## Маршрут проверяющего

1. [README](../README.md): назначение, четыре входа и статус запуска.
2. [Архитектура](ARCHITECTURE.md): существующие модули, поток данных и границы проверки.
3. [Контракт](../contracts/AGENTS.md): десять полей `answers.json`; Q5 отдельно.
4. [Проверки](../tests/AGENTS.md) и [журнал](review.md): ожидаемые случаи, фактические результаты и решения владельца.

Основные объекты оценки — точность Q1–Q4, пересчёт на новых файлах, коммуникация Q5 и реальная работа с AI. Закрытый эталон до сдачи недоступен. В ТЗ указан срок 48 часов с получения; момент получения здесь не установлен.

## Просмотр кода

`solve.py` — тонкая точка входа. `src/akfurs/solver.py` связывает существующие предметные модули; `output.py` собирает и проверяет десятипольный контракт. Подтверждение — в соответствующих тестах и локальных сверках. Существующие модули и оставшиеся проверки указаны в архитектуре.

Не принимай наличие схемы за доказательство численной точности, проверку цитат за проверку смысла Q4 или сохранённый JSON за воспроизводимый расчёт. Тест на изменённом входе должен менять результат без ручного редактирования ответов.

## Будущая демонстрация

Первый полный живой сценарий общего CLI испытан; новая демонстрация проводится только по отдельному разрешению:

1. Использовать проектную `.venv` и разрешённый доступ к AI по инструкции README; зависимости не устанавливать без согласования.
2. Положить новую версию четырёх исходных файлов в `data/` без правки содержимого.
3. Запустить `python solve.py data/ > answers.json`; получить только JSON в stdout и проверить все десять полей.
4. Показать контрольные числа и локальные основания Q1–Q4, особенно новый чат и изменение порядка приглашения/цены.
5. Показать реально найденную ошибку агента, способ обнаружения и проверку исправления.

Владелец снял внутренний критерий трёх успешных прогонов: одного полного проверенного запуска достаточно для дальнейшей работы. Изменённые входы пока проверены синтетически. Запрошенная модель, версия CLI, способ доступа и обработка ошибок Q4 описаны в README и журнале. Provider model/effort/snapshot CLI не сообщил, они остаются NOT_CHECKED. Секреты не передаются в коде.

## Одно итоговое письмо

| Элемент | Что проверить |
|---|---|
| `answers.json` | Финальный программный пересчёт строго по исходному шаблону |
| Код: GitHub-ссылка с доступом либо ZIP | Без исходных данных; реальная история разработки |
| Q5a и Q5b | Записка на полстраницы с тремя выводами и двумя рекомендациями; корректный ответ C0010 |
| Подтверждение работы с AI | Подлинный экспорт или скриншоты после проверки содержимого |
| Ошибка агента | 2–3 предложения о реальном случае, обнаружении и исправлении |

Q5 и AI-экспорты до передачи хранятся локально в `private/`; исходные сообщения не добавляются в Git. Если письмо работодателя задаёт иной формат сдачи, сверить его до отправки.

Локальный кандидат включает побайтную копию первого проверенного JSON, отдельный Q5, кодовый ZIP, настоящий bundle семи коммитов и patch незакоммиченных изменений, очищенный экспорт видимых сообщений с происхождением, описание реальной ошибки и черновик письма. Экспорт не заявляется полной внутренней сессией. `run_command` принятого JSON сохраняет реальные абсолютные пути исходного запуска; переносимый эквивалент для нового каталога дан в `RUN_README.txt`. Среда работодателя не проверена.

Этот состав относится к историческому кандидату G07. В G08 формируется
новый комплект из зафиксированного кода: code ZIP, его manifest и bundle
должны указывать один commit. Исторический patch остаётся в прежнем
комплекте; он не подменяет окончательную версию кода. Техническая таблица
R3 и карта происхождения результатов передаются Ивану отдельно от
облегчённого комплекта для работодателя. Приёмка R1/R2/R3 сохраняет
собственные статусы; подготовка G08 не создаёт решения владельца.

## Доступ и история

Репозиторий выбран приватным. Перед сдачей отдельно проверить доступ получателя по подтверждённому аккаунту; текущее оформление не подтверждает его доступ. При передаче ZIP проверить состав и отдельно обеспечить разрешённую передачу истории. Не включать `.git` без проверки всей истории.

Коммиты должны отражать реальные изменения. Не создавать искусственные промежуточные версии, фиктивные `fix` и успешные проверки. Изменение смыслового правила не смешивать с массовым форматированием.

Перед разрешённой публикацией проверить `git status --short`, `git ls-files`, `git diff --cached --name-only` и доступную историю. Эти команды сами по себе не являются сканированием секретов; при попадании данных в историю публикация останавливается.

## Условия отправки

- Подтверждены R0–R3 в едином журнале; внутренние критерии проекта не выданы за требования работодателя.
- CLI пересчитывает Q1–Q4 на новых входах; JSON соответствует шаблону, нет вшитых ответов и существенных необъяснённых расхождений.
- Выполнены численные сверки, проверка Q4 с указанным охватом, повторные и изменённые запуски; ограничения названы честно.
- Q5 согласован с принятыми расчётами и контекстом C0010; AI-доказательства подлинные и безопасны для передачи.
- Получателю доступен полный комплект; исходные данные и секреты отсутствуют в публикуемых файлах и истории.

Отсутствие обязательного элемента, невоспроизводимый запуск, существенный дефект или утечка блокируют отправку. При дефиците времени приоритетны безопасность, корректный пересчёт, новые входы, Q5 и AI-доказательства; косметика не должна задерживать готовую сдачу.
