# Контракт результата

Область: формат `answers.json` и [answers.schema.json](answers.schema.json). Первичный источник — локальный `inbox/answers_template.json` вместе с ТЗ. `src/akfurs/output.py` проверяет схему и взаимные ограничения; наличие схемы не доказывает предметную правильность.

## Поля

Итоговый объект содержит ровно десять ключей:

| Ключ | Ожидаемое значение |
|---|---|
| `q1_unique_orders` | Количество уникальных заказов, целое число |
| `q1_unique_order_lines` | Количество уникальных строк, целое число |
| `q2a_paid_orders_without_payment` | Массив числовых номеров заказов |
| `q2b_unidentified_payments_count` | Количество поступлений, целое число |
| `q2b_unidentified_payments_sum_rub` | Сумма в рублях, число |
| `q3_price_violation_lines_total` | Количество строк, целое число |
| `q3_price_violation_lines_by_manager` | Объект «каноническое имя → целое количество» |
| `q4_chats_meeting_before_price` | Массив ID чатов без повторов |
| `run_command` | Строка с фактически проверенной командой полного пересчёта |
| `notes` | Строка с трактовками, влияющими на ответы |

Поясняющие строки и пример имени менеджера из шаблона не являются ответами. Номера заказов передавай числами без `A-` и ведущих нулей. Q5 и внутренние основания событий не добавляй в JSON.

## Правила изменения

- Создавай схему только после сверки полного исходного шаблона и ТЗ; запрещай дополнительные поля. Не объявляй наличие машинной валидации по одной текстовой таблице.
- Формируй итог программой; не заполняй шаблон вручную и не выпускай частичный JSON при ошибке.
- Сохраняй порядок ключей шаблона для удобства просмотра; порядок массивов зафиксируй при реализации и проверяй повторным запуском.
- Структурная проверка не доказывает правильность расчётов, соответствие менеджеров справочнику или смысл Q4. Численные сверки и проверка источников обязательны отдельно.
- Меняй трактовки через [журнал решений](../docs/review.md), отражай существенное в `notes`, пересчитывай зависимые результаты и проверки.

Реализованное проектное правило порядка: числовые номера Q2a и строковые ID Q4 сортируются по возрастанию; ключи менеджеров — лексикографически. В разбивку Q3 входят только положительные группы. Проверяются сумма менеджеров, границы количества строк/заказов, уникальность массивов и нулевая сумма при нулевом количестве неопознанных поступлений. Это дополнительные внутренние инварианты, а не новые требования работодателя.
