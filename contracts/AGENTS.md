# Контракт результата

Область: `answers.json` и [answers.schema.json](answers.schema.json). Первичный источник — локальный `inbox/answers_template.json` вместе с ТЗ. `src/akfurs/output.py` проверяет схему и взаимные ограничения; схема не доказывает предметную правильность.

## Поля

Итоговый объект содержит ровно десять ключей:

| Ключ | Ожидаемое значение |
|---|---|
| `q1_unique_orders` | Количество уникальных заказов, целое число |
| `q1_unique_order_lines` | Количество уникальных строк, целое число |
| `q2a_paid_orders_without_payment` | Массив числовых номеров заказов |
| `q2b_unidentified_payments_count` | Количество поступлений, целое число |
| `q2b_unidentified_payments_sum_rub` | Сумма в рублях, число |
| `q3_price_violation_lines_total` | Количество строк, целое число |
| `q3_price_violation_lines_by_manager` | Объект «каноническое имя → целое количество» |
| `q4_chats_meeting_before_price` | Массив ID чатов без повторов |
| `run_command` | Строка с фактически проверенной командой полного пересчёта |
| `notes` | Строка с трактовками, влияющими на ответы |

Поясняющие строки и пример имени менеджера из шаблона не являются ответами. Номера заказов передавай числами без `A-` и ведущих нулей. Q5 и внутренние основания событий не добавляй в JSON.

## Сохранение контракта

- Схема уже есть. Не создавай вторую схему и не меняй `answers.schema.json` без отдельного разрешения и сверки с полным исходным шаблоном и ТЗ.
- Формируй итог программой. Не заполняй шаблон вручную и не выпускай частичный JSON при ошибке.
- Сохраняй реализованный порядок ключей. Массив Q2a сортируй по числовому номеру заказа, массив Q4 — по ID чата. Ключи менеджеров сортируй лексикографически; в разбивку Q3 включай только положительные группы. Это закреплено в `src/akfurs/output.py` и тестах.
- Проверяй сумму групп Q3, границы числа строк/заказов, уникальность массивов и нулевую сумму при нулевом числе неопознанных поступлений. Это внутренние инварианты проекта, а не новые требования работодателя.
- Структурная проверка не доказывает правильность расчётов, соответствие менеджеров справочнику или смысл Q4. Проверяй числа и источники отдельно.
- Меняй трактовки через [журнал решений](../docs/review.md), отражай существенное в `notes` и проверяй зависимые результаты.
